# License Boundaries and Commercial Runtime Permissions

Roblox Game Forge uses a dual-boundary licensing structure designed to protect the developer tooling while giving game creators complete freedom to build, publish, and monetize Roblox games.

## Executive Summary

1. The developer framework and CLI are source-available under the Sustainable Use License v1.0 (SUL v1.0).
2. The game runtime components and first-party generated output are subject to the Commercial Game Runtime Exception.
3. You can publish and monetize Roblox games made with Forge without royalties or fees.
4. You cannot resell or host the Forge developer tooling as a competing commercial product or cloud service. Free non-commercial distribution remains governed by base SUL terms.
5. Third-party assets, platform audio, and external model outputs remain subject to their upstream terms and are not automatically licensed by Forge.
6. This software is source-available. It is not open source under OSI definitions.

## Boundary Map

The table below clarifies which license terms govern each directory in the repository:

| Path / Component | Description | Governing License | Commercial Game Use | Tool Resale / Hosting |
| --- | --- | --- | --- | --- |
| `cli/` | Forge Lune CLI, commands, and authoring tools | SUL v1.0 | Internal development only | Paid resale and hosting prohibited |
| `core/` | Shared domain logic, infra adapters, anticheat, ui-kit | SUL v1.0 with Runtime Exception | Fully permitted in Roblox games | Prohibited as standalone paid tool |
| `genres/` | Reusable genre loop modules and QA templates | SUL v1.0 with Runtime Exception | Fully permitted in Roblox games | Prohibited as standalone paid tool |
| `games/<pack>/src/` | Game-specific Luau gameplay logic | Creator owned / Runtime Exception | Fully permitted in Roblox games | Governed by creator |
| Generated Assets | Meshes, audio, icons generated by Forge pipelines | Runtime Exception / Provider License | Permitted for first-party procgen; third-party depends on provider | Governed by provider terms |
| `skills/` | Agent skill definitions for AI workflows | SUL v1.0 | Internal development only | Paid resale and hosting prohibited |

## What Game Creators Can Do

Game creators who adopt Roblox Game Forge have permission to:

- Build interactive experiences using the CLI and agent workflows.
- Embed runtime code from `core/` and `genres/` into their published Roblox place files (`.rbxl`).
- Distribute compiled or bundled Luau scripts inside published Roblox experiences.
- Generate revenue from in-experience passes, developer products, paid access, and engagement-based payouts.
- Keep 100% of game earnings without paying any royalty or revenue share to Forge maintainers.
- Customize, fork, and adapt runtime modules for their specific games.

## What Is Prohibited

The Sustainable Use License prevents commercial exploitation of Forge as a developer tool platform. You may not:

- Package the CLI or generator tools into a paid commercial software product.
- Offer Forge as a hosted software-as-a-service (SaaS) or cloud generation platform to third parties for payment.
- Sell access to a hosted web interface or API wrapping the Forge toolchain.
- Re-license the developer tooling under permissive or alternative commercial terms.

Free redistribution of the software for personal or non-commercial purposes remains allowed under the base Sustainable Use License.

## Asset Provenance and Deterministic Manifest Checks

All assets in a game pack are audited by deterministic license checks before build or packaging:

1. Allow-list Verification: Every asset in `games/<pack>/assets/manifest.yml` must trace to an allowed tool in `cli/forge/lib/licenses.luau` or provide verifiable rights evidence.
2. Tool Approval Is Not Asset Clearance: The fact that a tool is registered in the allow-list means the framework permits running it. It does not grant blanket commercial rights over every asset produced by that tool. Third-party provider terms must be verified individually.
3. Banned Model Protection: Models with non-commercial or geographically restricted licenses (`audiocraft`, `roblox-cube`, `hunyuan3d-2`) are permanently rejected by the validator.
4. Packaging Gate: Packaging workflows refuse builds containing unknown, unverified, or rejected asset tools.
5. Separation of Lawfulness from Quality: A valid license allows an asset to pass the legal gate, but quality approval requires independent review evidence.
