## Decoder and evaluator mechanism

After authorization for real probes, invoke the resolved local decoder with explicit argument arrays, hidden windows, disabled stdin interaction, bounded lifecycle cancellation and task-owned outputs. First inspect actual container streams and frame/sample timestamps with ffprobe. Then decode selected video and audio stream IDs from the same original container with FFmpeg, failing on corruption rather than accepting a partially decoded prefix. Capture literal argv, executable/version identity, stdout/stderr, exit status and input/output hashes. Do not run these proposed commands during preparation.

An implementable sequence is ffprobe JSON `-show_streams -show_format -show_frames`, followed by FFmpeg `-nostdin -v error -xerror -i <original>` with explicit `-map 0:<stream-index>` for the selected track. Video decoding retains every decoded frame and its PTS mapping; audio decoding retains PCM samples, channels, sample rate and PTS mapping without silence insertion, normalization or a substituted cue file. Preserve timestamps from the original rather than inventing constant frame cadence from frame numbers. Reconcile decoded counts, actual final timestamps and full required interval coverage. Derivatives retain parent container hash, stream ID and transformation arguments. Originals remain authoritative.

Compute per-interval non-finite/clipped/zero-sample counts, level statistics, decoded duration, missing timestamps and repeated-frame runs as structural evidence only. Static video during expected movement must not pass because frame count is high; temporal evaluation must observe actual scene/action change. Silence during expected cues cannot pass because a WAV header or hash is valid. Nonzero levels cannot prove correct cues.

Its capability receipt must identify executable/model/version, commercial-use basis, actual audio/video transport, supported codecs/limits and a successful owned capability probe. Nine deferred adversarial probes:

1. Silent audio with valid container/hash: missing expected audible cues cannot approve.
2. Swap audio from another session or generated cue WAV, recomputing file hashes: recorder/source/session proof must reject it.
3. Truncate audio/video, including a decodable prefix: incomplete action/tail coverage must reject or remain inconclusive.
4. Repeat one frame across a nominal-duration video: static substitution cannot satisfy motion observation.
5. Missing, nonworking or unsupported decoder: exact capability/exit failure, never successful skip.
6. Actor/session/process/build mismatch, even with plausible observations: reject before authority.
7. Image-only model claiming it heard cues: absent real audio delivery/listening capability forces inconclusive.
8. Shift PTS, introduce clock drift or remove frames/samples around an action: fail synchronized coverage against frozen bounds.
9. Change original bytes or manifest/observations after decode/snapshot, or replay an old run attestation: reject stale bindings; retain both failure evidence and original source.
