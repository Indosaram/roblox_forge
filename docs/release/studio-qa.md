# Studio QA lifecycle

## Explicit owned bootstrap

After the source barrier and validated marked build, run the single-session capture scenario:

```text
lune run cli/forge qa run --pack primal-isles --scenario release-first-play --studio --bootstrap-owned --studio-receipt <owned-config-document.json> --evidence <owned-run-evidence.json>
```

The config document contains `driver`. Its capability claims authorize nothing during
explicit bootstrap. Marked artifact, sidecar and current source checks still run,
followed by the same owned lifecycle. The command writes run evidence and
`<owned-run-evidence.json>.discovery.json` after cleanup. Availability requires
observed runtime admission, subscribed input and validated original client captures.
Failed or partial runs retain unavailable fields, blockers and cleanup evidence.
The discovery document contains no persistence bearer token and is not a driver config.
Without `--bootstrap-owned`, normal readiness checks remain required.

The owned editor must be launched into the interactive user session. A caller running
on a service window station (session 0) cannot read the interactive user's Studio
session, so the editor boots to the login dialog, never publishes an MCP datamodel,
and admission fails after the full registration window (measured: seven secure-storage
logon-session failures and a login dialog in the launch's Studio log, versus none on a
session 1 launch). Invoke the run through the scheduled QA bat
(`schtasks /create ... /it`) rather than a direct shell command; the receipt's
`driver.desktop` stays `interactive`, and the launched editor's reported `desktopName`
is the desktop the registration helper must open.

Bootstrap does not bypass `TOUCH_INPUT_UNAVAILABLE`,
`SOURCE_ACTOR_PROCESS_UNPROVEN`, listening or independent-reference requirements.
Native window enumeration is not actor registration. Initial discovery uses a
single epoch; first-epoch F8 rows do not prove input in freshly rejoined clients.

## Explicit owned-QA artifact preparation

Normal builds stay unmarked. An authorized caller may invoke
`buildtargets.runTarget(target, ownedQaToken)` with a unique 16-128 character
alphanumeric/hyphen ownership marker and a distinct owned output path. This is
a library option, not a new CLI flag. `buildidentity.prepare` places the marker
on ReplicatedStorage through the temporary Rojo overlay before building;
the authored pack is never modified. The sidecar binds `ownedQaToken` and the
exact artifact hash. `inspectArtifact(bytes, identity, ownedQaToken)` checks both
the marker and exact identity script source; omitting the token requires an
unmarked artifact. Do not patch the place after hashing.

After the source barrier and validated build, assemble the runtime driver
configuration with the installed editor
`C:/Program Files/Roblox/Versions/version-76e1a02649ad4f35/RobloxStudioBeta.exe`,
adjacent `StudioMCP.exe` as command with `args: []`, the resulting owned buildPath,
its packDir, sidecar identity as buildIdentity, and sidecar ownedQaToken as
ownershipToken. Select distinct absent task-owned artifactDirectory and
persistence.directory paths. Namespace/port must match the actual local host;
its bearer token is runtime-only and is not the ownership marker. No actual
token/config file or artifact is generated by these instructions.

StudioSession checks token, sidecar identity and artifact bytes before spawning.
qastudio's consumer must pass the sidecar token into inspectArtifact and require
it equals config.ownershipToken. Connected instances are only observed and
matched, never marked to adopt them. Existing baseline instances remain excluded.
These are local attestations, not cryptographic signatures or hostile-local-user
isolation. Private-desktop launch and cleanup remain subject to real validation.

Status: the owned launch/registration/admission/rejoin path is live-validated
(2026-10-05 release-rejoin PASS on the post-cleanup build: 27/27 steps, two
physical transitions each carrying five load-evidence proofs, zero lifecycle
residuals); artifact preparation itself remains authored and is re-verified on
every owned run by `validateOwnedArtifact`. Historical schemas and receipts are
provenance only, never current proof.

## Production entry

`qastudio.luau` verifies exact build identity/artifact source and invokes
`studio-driver.mjs`. The CLI owns MCP transport before initialization, then
`runOwnedStudio` starts optional persistence and calls
`StudioSession.launch(config, players)`. Configuration requires MCP command and
args, editor.executable, buildPath, ownershipToken and artifactDirectory.
The successful session returns actual serverId, clients and process identity.
Configured preexisting IDs do not establish launch ownership.

Discovery validates actual tools/list parameter/enum schemas. The historical
route uses execute_luau(Edit) and StudioTestService:ExecuteMultiplayerTestAsync,
not an invented start_test API. No eight-client limit is claimed. Inventory
requests at process/start response boundaries identify token-bound actors;
missing registration fails explicitly and closes the owned Job. No sleep or
poll-to-pass loop is used. Asynchronous registration timing remains a real
integration concern for consolidated validation.

## Process ownership and cleanup

`studio-driver-process.mjs` creates a private non-input desktop without switching
the Windows input desktop. A suspended editor is assigned to a no-breakaway,
kill-on-close Job with completion port before resumption. The retained handle,
PID, creation time, artifact command line and baseline exclusions are recorded.
Children inherit Job membership. Cleanup targets only this Job and requires
ACTIVE_PROCESS_ZERO plus supervisor closure; missing release receipt remains
unresolved even when supervisor termination closes the Job handle.

`StudioLifecycle.attempt` precedes allocation; `acquire` records the real handle.
`release(row)` disposes one owned resource idempotently without closing the
host/transport. `close()` disposes all in reverse order with bounded cleanup
budgets. Failed cleanup retains residuals and blocks success. SIGINT/SIGTERM
initiate owned cleanup. No process-name termination, GUI manipulation, multi_edit
or native gameplay fallback is permitted.

## Local durable host and physical rejoin

Optional config.persistence contains an absent owned directory, namespace,
port and runtime-only token. `openOwnedPersistence` creates that directory,
starts Task9's authenticated 127.0.0.1 SQLite host, checks actual `.ready`, and
retains DB/WAL evidence after stopping the host. The host is outside editor Jobs
and survives their crashes/restarts. Existing user directories are refused.
The scheduled QA bats purge the private run directory before each attempt, so the
exclusive-creation check never meets the previous run's retained evidence; the
driver itself never deletes an existing path.

Before play, the owned Edit model receives a transient ServerStorage folder
ForgeOwnedPersistenceConfig with Mode/Namespace/Port/Token attributes.
RuntimeBackend consumes and destroys it. No Source or built artifact is patched;
token is neither shipped nor written to evidence. Each restarted editor gets
the same runtime configuration while the host remains alive.

`StudioSession.restart` observes acknowledged persisted wrappers, ends the
owned test, proves old Job exit, opens a fresh lifecycle/transport/editor and
remaps both stable actors to distinct Studio IDs. It compares actual backend
acquisition input against prior committed data and verifies both actors loaded.
The driver checks fresh schema1 loaded identities, preserves scalar bindings,
invalidates transient subscriptions/devices and emits epochs/transitions.
Device setup must be repeated on replacements.

Load proof is deferred and observed, never assumed: `observeRejoinLoads`
subscribes the actual durableRevision/leaseGeneration commit proofs, the scenario
end fills any still-pending observation, and an error path deletes the pending
marker so a failed attempt cannot satisfy a later one.

`writeRejoin` writes physical-rejoin.json separately from first-play evidence,
plus hashed capability, per-epoch backend context, actor commit/close/load proofs
and original capture references. evidence.rejoin names the main document;
evidence.rejoinArtifacts names every referenced proof and original capture.
Verified capability fields are emitted only after measured replacement/exit/load
conditions hold, never from configuration alone. Task11 owns independent gate
validation and review digests. This authored producer is not acceptance proof.

## Durable crash

`session.crashAtBarrier({key,requestId,phase,trigger,buildIdentity,namespace})`
subscribes actual ForgePersistence.BarrierReached before armBarrier and trigger.
Trigger acknowledges dispatch rather than waiting for blocked owner ACK.
The driver reads barrierStatus from the owned runtime, verifies exact held
ticket/request/key/phase/namespace/build and expiration margin, then closes only
the editor Job. RuntimeBackend expiry throws before owner ACK. No caller JSON
or arbitrary callback ticket is authority. Restart uses a new lifecycle and
transport, same host namespace/artifact. Full cleanup remains required afterward.

## Scenario observations

Path begin subscribes to production ForgeWildlifePathObserved; path end keeps
listening until ordered matching NPC/serial request, failure, consumption and
recovery/refusal appear, with a bounded deadline. Missing and unrelated events
cannot satisfy it. Refused prompt evidence requires real terminal reason,
unchanged deep inventory and authoritative node version/charges. Walk arrival
honors optional verticalToleranceStuds at both client and server.

Contention subscribes both actors before either input, observes actual
ForgeGatherRequested versions and request times, requires overlapping requests,
one confirmed/one allowed terminal refusal, final node charge 1 to 0, unchanged
loser bag and conserved catalog gain. It never freezes versions or retries a
loser into success. Missing loser request/result fails bounded.

Touch is explicitly unavailable in inspected product schemas: op touch fails
TOUCH_INPUT_UNAVAILABLE before input (release-first-play contains 11 touch
steps). Mouse/keyboard cannot be labelled touch.

Server boot and join survive predecessor ProfileStore locks with bounded retries
(production entry constructs the survival factory with a `locked` retry up to
150s; `Server.join` retries a locked acquire for 90s before any kick and records
the reason in the `ForgeLastKick` attribute). Client identity mapping waits on
the `Players.LocalPlayer` property — the instance is named after the username,
so `WaitForChild('LocalPlayer')` never resolves — and admission re-observes one
live-LocalPlayer window per player until the identity set is stable. The
scheduled bats also purge orphaned QA-owned Studio windows (artifact command
line plus direct children) before each attempt so restart discovery cannot
admit a dead window.
Native audiovisual producer integration is pending the active capture owner's
exact API; still screenshots are not audio/video proof.

## Observed Studio MCP surface

The configured host (`StudioMCP.exe`, server `RobloxStudio` 1.0.0) was queried
directly with `initialize` + `tools/list`; 28 tools were returned. The input
surface is `user_mouse_input` and `user_keyboard_input` only: there is no touch
or gesture tool, which is why `op: touch` cannot pass through this channel and
why mouse/keyboard must never be relabelled as touch. The remaining relevant
tools are `list_roblox_studios`, `get_studio_state`, `execute_luau`,
`screen_capture`, `start_stop_play`, `wait_job_finished` and `inspect_instance`.
The inventory response shape is `{studios: [{id, ...}]}`.

Measured registration behaviour: a freshly started editor registers
asynchronously, so admission observes `list_roblox_studios` against a bounded
deadline (`registrationTimeoutMs`, default 180000) instead of a single immediate
listing, and the multiplayer actors are observed the same way after the start
response. Both loops stop as soon as the required registration is observed or
the deadline expires with the precise failure code; they never retry a missing
actor into success. A client that has registered but not finished loading its
Luau bridge reports a transient `Target is not reachable`; step calls retry only
that specific failure inside the scenario deadline.

`execute_luau` runs against Studio's Assistant command path, which cannot yield
across MCP calls (`cannot cancel thread`), so wait-style steps are written as a
single invocation with an inline eventWait/observe helper and their trigger
elsewhere — proven by the passing release-rejoin run (all 27 steps, including
wait_for, device, identity mapping and snapshots). The same path truncates long
results around 100,015 characters, so `fetchPersistenceSnapshot` chunks the
persistence snapshot into at most 90,000-character StringValue parts.
