## 1. 신규 바이옴: 잿빛 해안

- **위치:** 탐사 항로의 새 모듈 계열입니다. 계획 §5.3의 P1 후보 "화산 해안"을 시즌 1 바이옴으로 씁니다.
- **풍경:** 검은 모래 해변, 식은 용암 바위 지대, 온천 웅덩이, 화산재가 쌓인 관목 숲. 실제 화산섬 식생(양치류, 이끼, 염생 식물)으로 팔레트를 만듭니다.
- **노출 유형:** 열기. 온천 주변과 분기공 근처에서 노출 게이지가 오릅니다. 새 장비 "재막이 망토"로 저항 점수를 얻습니다.
- **난이도 밴드:** 거친(2)과 험한(3)에만 나옵니다. 진입은 장비·저항 점수 게이트입니다(계획 §5.4).
- **템플릿 모듈:** 바이옴 1 × 위험도 2(거친, 험한) × 변주 2 = 4개 추가. 저장 형식은 기존과 같은 template + seed + delta이고, 항로 교체 주기 24시간(ADR-05)을 그대로 씁니다.
- **신규 재료(태그):** 흑요 조각(날카로움), 유황 결정(가연), 온천 점토(내열), 재 섬유(경량). 이 재료로 시즌 레시피 6개(도구 2, 건축 부품 3, 장비 1)를 엽니다.
- **출현 생물:** 기존 아키타입 6종의 변종 4종(열에 강한 개체 등급) + 보스형 1(§2).

## 3. 스토리 비트: 「가라앉은 조류표」

계획 §9.1의 전제("조수 균열", 열린 미스터리)를 한 걸음 진행합니다. 세력 3개(항로 측량회, 장인 길드 연합, 섬 생태 보존단)를 모두 씁니다.

1. **발단(1주차):** 항로 측량회 연락원이 잿빛 해안 앞바다에서 돌판 조각을 건졌다는 소식을 전합니다. 조각에는 조수의 높낮이를 기록한 듯한 홈이 새겨져 있습니다.
2. **조사(2~3주차):** 일일 의뢰에 "돌판 조각 회수"가 섞입니다. 섬 생태 보존단은 바위등 거수가 조각 근처에만 둥지를 튼다는 관찰 의뢰를 냅니다.
3. **해독(4주차):** 장인 길드 연합이 조각을 맞출 틀을 만듭니다(공동 프로젝트). 서버 전체가 조각을 모은 수만큼 해독 진행도가 오릅니다.
4. **결집(5주차):** 해독된 조류표는 섬이 떠오르는 시각에 규칙이 있음을 보여 주지만, 마지막 줄이 비어 있습니다.
5. **여운(6주차):** 비어 있는 마지막 줄은 다음 시즌의 단서로 남깁니다. 비극적 반전 없이 "함께 맞춘 것이 남는다"는 정서로 닫습니다.

- 구현: 의뢰는 survival-coop Contracts, 챕터 공개는 `Schedule.luau` + 주입 clock(계획 §9.3).
- 대사는 팩 locale/strings.csv에 새로 씁니다. 출처 검사 게이트를 통과해야 합니다.

| 매칭 | 리그 점수가 비슷한 캠프끼리. 상대가 없으면 라운드를 열지 않고 다음 라운드로 넘깁니다 |

## 6. 6주 캘린더 템플릿

시즌 시작 시각 `S0`는 주입 clock 기준 초 단위 값으로 넣습니다. 서버 시계를 직접 읽지 않습니다(계획 D-8). 모든 이벤트는 `core/infra/liveops/Schedule.luau`의 `Schedule.new({ EventSpec })`로 등록하며, 같은 id를 두 번 쓰거나 `endsAt <= startsAt`이면 생성 시 오류가 납니다(Schedule.luau `normalize`).

| 주차 | 기간(S0 기준 일) | 이벤트 id | 내용 | 기능 플래그 |
| --- | --- | --- | --- | --- |
| 1 | 0 ~ 7 | `s1-biome-open` | 잿빛 해안 항로 개방, 스토리 발단 | `s1_ashshore` |
| 1 | 0 ~ 42 | `s1-season` | 시즌 전체(시즌 칭호 진행도, 코스메틱 판매) | `s1_season` |
| 2 | 7 ~ 21 | `s1-story-fragments` | 돌판 조각 회수 의뢰 섞임 | — |
| 2 | 7 ~ 42 | `s1-boss` | 바위등 거수 둥지 활성 | `s1_boss` |
| 3 | 14 ~ 42 | `s1-reef` | 소금관 암초 신청과 라운드 개방(P2) | `s1_reef` |
| 4 | 21 ~ 28 | `s1-decode-project` | 서버 공동 해독 프로젝트 | — |
| 5 | 28 ~ 35 | `s1-story-gather` | 조류표 결집 장면 공개 | — |
| 6 | 35 ~ 42 | `s1-finale` | 여운 장면, 리그 마감, 시즌 칭호 지급 | — |

배율(`multipliers`)은 **결정적 수량에만** 씁니다. 예를 들어 이벤트 의뢰의 조개돈 보상량입니다. 드롭 확률, 제작 성공률, 조련 판정 같은 확률 값에는 쓰지 않습니다. 배율은 무료 이벤트에만 붙이고 유료 상품과 연결하지 않습니다(ADR-07 규칙 2·4).

```lua
-- 템플릿: 팩 코드에 그대로 넣지 말고, 값 확정 후 사람이 머지하는 PR로 옮긴다.
local Schedule = require(path.to.core.infra.liveops.Schedule)

local DAY = 86400
local function at(S0: number, days: number): number
	return S0 + days * DAY
end

local function season1(S0: number)
	return Schedule.new({
		{ id = "s1-season", startsAt = at(S0, 0), endsAt = at(S0, 42) },
		{ id = "s1-biome-open", startsAt = at(S0, 0), endsAt = at(S0, 7) },
		{ id = "s1-story-fragments", startsAt = at(S0, 7), endsAt = at(S0, 21) },
		{ id = "s1-boss", startsAt = at(S0, 7), endsAt = at(S0, 42) },
		{ id = "s1-reef", startsAt = at(S0, 14), endsAt = at(S0, 42) },
		{
			id = "s1-decode-project",
			startsAt = at(S0, 21),
			endsAt = at(S0, 28),
			multipliers = { contractCoinReward = 1.5 }, -- 결정적 수량만
		},
		{ id = "s1-story-gather", startsAt = at(S0, 28), endsAt = at(S0, 35) },
		{ id = "s1-finale", startsAt = at(S0, 35), endsAt = at(S0, 42) },
	})
end

-- 사용: now는 주입 clock 값
-- local schedule = season1(S0)
-- schedule:active(now)                         -- 지금 열린 이벤트
-- schedule:multiplier("contractCoinReward", now) -- 겹친 이벤트 배율의 곱
-- schedule:next(now)                           -- 다음 시작 이벤트
```

- 공지: 각 이벤트 시작 시 `Broadcast.announce(kind, data)`로 서버 전체에 알립니다. 반복 전달에 안전한지는 수신 측 멱등 기록으로 확인합니다(docs/release/rollback.md "Recovery after an uncertain result").
- 기능 노출: `FeatureFlags.new(defaults)`의 기본값을 false로 두고, 스테이징 확인 후 켭니다. 프로덕션 변경은 사람 머지 PR입니다.
- 시험: 시즌 QA는 주입 clock으로 `S0 - 1`, 각 경계 시각, `S0 + 42일`에서 `active` 결과를 고정하는 spec으로 만듭니다. 경계 직전·직후 판정이 바뀌는지 확인합니다(실패 가능한 QA).
