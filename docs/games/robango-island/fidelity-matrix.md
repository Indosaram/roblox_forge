# Robango Island late-service fidelity matrix

## Scope and authority

Robango Island does not claim 100% original parity with Durango. The target is the late online service before the December 2019 shutdown, not the February update alone, an early-service snapshot, or the offline creative mode. Original names, maps, dialogue, art and undisclosed numeric tables are not claimed to have been recovered.

Authority is `.omo/plans/robango-recovery-world-audit.md`, then the mandatory `.omo/drafts/robango-spec-index.md` and its individual catalogs. Binding corrections inside each catalog override retained proposals. All catalog filenames below resolve under `.omo/drafts/`. The required recipe count is **124**, superseding older 121-count prose. The 12 categories contain 72 authored nodes; the 20 archipelago layouts, 40 stage instances, 30 missions and eight chapters are design deliverables, not evidence of running content.

`CONFIRMED` identifies only the feature explicitly supported by the cited original evidence. It never promotes a whole Robango catalog to historical fact. `RECONSTRUCTED` identifies Robango-authored rules, numbers, layouts or adaptations without recovered final-build data. `HISTORICAL_EVENT` identifies dated content that cannot be assumed active at shutdown. Several rows necessarily contain both confirmed feature existence and reconstructed implementation detail.

The verification column below records the state at `204bda9` (2026-10-25). Every status cites its evidence; evidence paths without a prefix are under `.omo/evidence/robango-recovery/` (local, gitignored). Statuses:

- **IMPLEMENTED+GATED**: the named native scenarios and specs pass in the pre-commit gate for `204bda9` (`p7/gate129.json`: `head` 204bda9, `ok` true, `valid` true, 43 native scenarios recorded and replayed, specs, `build --all` and smoke all PASS). Native scenarios run Lune fixtures over the real Session and factory; they are not live servers.
- **STUDIO-SEEN**: a Windows Studio run with real input through Studio MCP recorded a PASS for the cited part, with the build named in the cited file. Studio device emulation is not a real phone.
- **LIVE-UNVERIFIED**: nothing was exercised on the published staging places. Since 2026-10-26 the staging places run `9d673db` (`p127/deploy-9d673db.log`; earlier `9dc99f7`, `p115/deploy-9dc99f7.log`), but no player session there is recorded.
- **BLOCKED**: needs something the agent cannot supply. Reasons: no real phone connection (no real-device run after 2026-10-20); a single Roblox account, so no two-account trade, camp, clan or teleport; live receipt not exercised (Robux spend needs owner approval).

No row is complete release acceptance: every row still needs the task-12 live evidence named in its QA column. See `qa-evidence.md` for the detailed records.
