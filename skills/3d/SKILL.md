# 3d

## When to use

- A game pack needs creature or prop meshes. **Default: keyless procedural generation**
  (`forge gen procedural`) from the pack's `assets/procgen.yml` - no API keys, no network,
  no upload. It covers the four creature archetypes (`quad|serpent|titan|biped`) and five
  prop archetypes (`egg|crystal|rock|tree|crate`).
- A pack needs a bespoke mesh the archetypes cannot express: fall back to the external
  mesh provider (`forge gen mesh`, TRELLIS, MIT).
- A generated mesh must be cleaned, imported into Studio, or stored in Git.
- You must decide which 3D generation tool is allowed under the license allowlist.

## Steps

1. Author or refresh `games/<slug>/assets/procgen.yml`: one entry per asset with `key`
   (the game id, e.g. `pyro-pup`), `kind` (`creature|prop`), `archetype`, `scale`,
   `body`/`accent` (and `eye` for creatures) as `[r, g, b]` 0-255, and a stable integer
   `seed`. Reuse the pack's existing palette/scale values so art stays consistent.
2. Generate the meshes and the runtime specs module - no keys needed:
   `lune run cli/forge gen procedural --pack <slug>`
   This reads `game.yml` `poly_budget` (creatures: first of `kaiju|creature`, fallback
   3000; eggs: `egg`, fallback 600; other props: `prop`, fallback 800), runs the pure
   `core/domain/procgen` generators under Lune, exits 1 if any mesh exceeds its budget,
   writes `games/<slug>/src/shared/ProcAssets.luau`, and upserts each key into
   `assets/manifest.yml` as `tool: forge-procgen`, `moderation: Approved`, `assetId: 0`.
   It prints `<key> <kind>/<archetype> tris=<n> budget=<b>` per asset.
3. Run `lune run cli/forge assets codegen --pack <slug>` so the manifest keys are
   reflected in `src/shared/Assets.luau`.
4. At runtime build models with
   `core/infra/render/ProcAssets.build(ProcAssetsSpecs, key)` (deterministic; falls back
   to hand-authored Part models when a key is missing).
5. Only for a bespoke mesh, use the external provider (TRELLIS, MIT):
   `TRELLIS_URL=<endpoint> lune run cli/forge gen mesh --pack <slug> --key <key> --prompt "<prompt>"`
   The CLI POSTs `{"prompt":...}` to `TRELLIS_URL`, expects GLB bytes, writes
   `games/<slug>/assets/mesh/<key>.glb`, and upserts the manifest as `tool: trellis`,
   `moderation: NotUploaded`. Preview without generating with `--dry-run` (exits 0).
6. Clean a bespoke GLB with a headless Blender script if needed, import it into Studio,
   save it as a `.rbxm` in the pack, and commit the `.rbxm` to Git.
7. Run `lune run cli/forge check` before committing.

## Rules

- API 1 generators own assets/<genre>/procgen.yml; assembly merges pack inputs.
  Keys use <genre>-... and artifacts cannot overwrite common files. Capabilities
  are ordered procedural/launchart/audio subsets, not generic genre-ID cases.
  Prop-only starters declare procedural/audio; never invent a creature to pass
  launchart's real-creature gate. Starter specs are not finished production assets
  or proof they render. Require separate permission-gated Studio/API visual proof.

- **Procedural is the default provider and needs no keys or network.** Prefer it over any
  external tool; keep the generated `ProcAssets.luau` in Git.
- Asset acceptance requires recorded provider/tool/version, recipe/input version,
  commercial rights source, ownership and current artifact digest. Lawful imported
  assets can pass provenance without passing visual quality; a tool name is not
  an appearance approval. The banned-model registry still applies.
- Compare real desktop/mobile captures against the pack's quality reference.
  `forge quality check --pack <slug>` verifies a current authorized receipt, not
  generation success. Regenerated assets invalidate earlier approval. Local
  moderation-not-applicable is separate from Roblox platform approval, and
  staging development status never implies release approval.
- **Roblox Cube is forbidden**: license is "academic or research purposes only".
- **Hunyuan3D-2 is forbidden**: license excludes Korea, EU, and UK.
- Blender MCP is forbidden in unattended pipelines: it executes arbitrary Python over a
  local socket.
- No web API mesh upload; `.rbxm` files are versioned in Git instead (plan §11.3 asset
  sync excludes 3D models).
- Git is the single source of code: never use Studio MCP `multi_edit`; the flow is disk
  edit -> lint -> Git -> Rojo sync.
- Do not modify `core/` or genre modules for a game-pack asset.

## Verification

- `forge gen procedural --pack <slug>` exits 0, prints one
  `<key> <kind>/<archetype> tris=<n> budget=<b>` line per asset with `tris <= budget`, and
  writes `src/shared/ProcAssets.luau` with the `-- GENERATED by forge gen procedural` header.
- Re-running it produces byte-identical specs (deterministic seeds) and does not duplicate
  manifest keys; `forge assets check --pack <slug>` passes with the `forge-procgen` entries.
- `forge gen mesh --dry-run` exits 0 and prints the provider, `TRELLIS_URL`, and the
  `games/<slug>/assets/mesh/<key>.glb` target path (bespoke meshes only).
- `lune run cli/forge check` exits 0 (selene, stylua check, luau-lsp, econ drift, specs,
  rojo build, built-place inspection).
